# Security Policy

## Supported Versions

This project is under active development. Security fixes are prioritized for
the latest code on the default branch. Older commits and unreleased snapshots
may not receive security updates.

## Reporting a Vulnerability

Please do not report security vulnerabilities through a public Issue, Pull
Request, or discussion.

Report vulnerabilities privately through one of the following channels:

1. Use GitHub's private vulnerability reporting feature for this repository, if
   it is enabled.
2. Otherwise, contact the repository maintainers through a private GitHub
   channel and mention that the report contains security-sensitive information.

Please include as much of the following information as possible:

- A clear description of the vulnerability and its potential impact.
- The affected component, file, endpoint, or configuration.
- Steps to reproduce the issue or a minimal proof of concept.
- The affected version, commit, or deployment configuration.
- Any suggested mitigation or fix, if available.

Please avoid including real credentials, personal data, or other sensitive
information in the report. Use redacted examples whenever possible.

## Response Process

Maintainers will acknowledge a valid report as soon as reasonably possible and
will investigate its impact and reproducibility. The resolution may include a
patch, configuration guidance, a workaround, or a recommendation to upgrade.

The disclosure timeline will be coordinated with the reporter. Please do not
publicly disclose the vulnerability until maintainers have had a reasonable
opportunity to investigate and prepare a fix.

## Security Updates

Security-related updates will be communicated through the repository's release
notes, advisories, or other appropriate project documentation when available.
